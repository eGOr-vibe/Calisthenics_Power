## 1. Концепция продукта

**Calisthenics Power** — это биомеханический ассистент калистеника для смартфонов. Не очередной таймер, а научно-обоснованный инструмент, который:

- строится вокруг **Профиля атлета** (антропометрия + здоровье + цели);
- считает **нагрузку на связки и суставы** через унифицированные формулы;
- **адаптивно пересчитывает тренировку на лету** при травмах/заменах;
- объясняет **«почему так»** с опорой на биомеханику, кинезиологию и доказательную физкультуру;
- обучает **ментальным и ЦНС-техникам** для продвинутой активации.

**Целевая аудитория (косвенно):** опытные одиночки-калистеники, тренирующиеся без тренера и программ, желающие научно обосновать свою интуицию.

**Платформа:** Mobile-first PWA (Next.js 16 + App Router), устанавливается на смартфон как приложение. Архитектура логики изолирована, чтобы в будущем можно было портировать в нативное мобильное приложение (React Native / Expo).

## 2. Цели итераций

### MVP (Фаза 1) — Адаптивный ВИИТ-таймер
- Профиль атлета (базовый) + матрица травм + индекс стресса
- Каталог упражнений калистеники (~50-60) с фильтрами, биомеханикой, научной базой
- Конструктор тренировок: AMRAP / EMOM / Tabata / Интервалы
- **Адаптивный таймер** с «быстрой заменой» упражнений прямо в круге и пересчётом объёма
- TTS-озвучка таймера + голосовое управление (пауза/стоп/следующий)
- История тренировок с базовой статистикой
- Библиотека техник (~15-20: ЦНС / ментальные / расслабление / разминка-заминка)
- Теоретический блок (10 разделов: биомеханика, кинезиология, физиология и т.д.)
- AI-ассистент с абстракцией провайдера (Z.AI / WebLLM / кастомный URL для локальной LLM)
- 2 языка (RU/EN), 2 темы (свет/тьма), переключение
- Импорт/экспорт данных (JSON)
- Локальный профиль (без авторизации)

### Фаза 2
- Конструктор биомеханики (расширенный калькулятор нагрузки по тренировочному циклу)
- «Путь к статике» — прогрессии с гейтами (тестами-вратами): не держишь закрытый горизонт X сек → система не пускает дальше
- Интеграция техник как «пред-сет подсказки» перед подходом
- Голосовой ввод результатов кругов
- Графики прогресса (круги/объём/HRV по неделям)

### Фаза 3
- 3D-визуализация упражнений (скелет с мышцами, векторы сил)
- «Слайдер ошибок» — ползунок нарушения техники с визуализацией последствий
- Социальный слой: карта уличных площадок, общение с другими атлетами
- Авторизация и аккаунты (облачная синхронизация)

### Будущее
- Нативное мобильное приложение (React Native / Expo)
- Расширенный каталог (Crossfit, гири, йога)
- ИИ-генерация программ под цель

## 3. Пользовательские сценарии MVP

### Сценарий A: Быстрая AMRAP-тренировка
1. Пользователь открывает приложение → видит на главном экране кнопку «Быстрый старт»
2. Выбирает формат AMRAP, длительность 30 минут
3. Выбирает шаблон «Мод. Синди» (5 подтягиваний + 10 брусья + 15 кор)
4. Запускает таймер → слышит «Круг 1, пошёл»
5. В середине 5-го круга срывает мозоль → тапает по упражнению «Подтягивания» → видит модалку «Заменить»
6. Выбирает «Австралийские подтягивания» → видит разницу: «Коэф. нагрузки 4 → 1, объём ×4 = 20 повторений»
7. Подтверждает → таймер продолжает, остаток кругов идёт с заменой
8. Завершает за 27:44, 20 кругов → видит итог: суммарная нагрузка на связки, общее число повторений
9. Оценивает самочувствие (1-10) → тренировка уходит в историю

### Сценарий B: Изучение техники
1. Пользователь хочет освоить «Горизонт» → открывает «Библиотеку техник»
2. Читает про «Изометрический взрыв» → видит научную базу и шаги
3. Переходит в «Теорию» → раздел «Биомеханика», читает про рычаги и центр тяжести
4. Спрашивает у AI-ассистента: «Как мне объединить изометрический взрыв с тренировкой горизонта?»
5. AI (через локальную LLM или Z.AI) отвечает с учётом профиля

### Сценарий C: Профиль и индекс стресса
1. Утром пользователь открывает приложение → видит «Обнови индекс стресса»
2. Вводит: сон 5 ч, настроение 4/10, забитость 7/10
3. Система считает `I_stress = высокий` → показывает предупреждение: «Сегодня лучше снизить интенсивность статики на 20%»
4. Пользователь добавляет травму в матрицу: «Левый локоть — медиальный эпинкондилит»
5. При выборе упражнений система фильтрует/маркирует травмоопасные

## 7. Формулы и расчёты (MVP)

### 7.1. Индекс нагрузки на связки (Tendon Load Index)
```
Total_Stress = Σ ( loadCoef_exercise × volume_exercise )
где volume = reps × rounds (для динамических)
            = duration_sec × 0.1 (для статики, эмпирически)
```
`loadCoef` — целое 1-9:
- 1 — австралийские подтягивания, подъём корпуса на пресс
- 2 — отжимания от пола классические, приседания
- 3 — отжимания на брусьях классические, L-сит
- 4 — подтягивания классические, отжимания лучника
- 5 — подтягивания на одной руке (негативные), отжимания псевдо-планш
- 6 — отжимания на одной руке (с опорой)
- 7 — передний вис (tucked), горизонт (tucked)
- 8 — передний вис (full), планш (straddle)
- 9 — планш (full), стойка на руках без опоры HSPU

### 7.2. Быстрая замена упражнений
```
K_difficulty = loadCoef_new / loadCoef_old
V_new = V_old × K_difficulty
```
**Пример:** замена подтягиваний (коэф 4) на австралийские (коэф 1):
- `K_difficulty = 1 / 4 = 0.25`
- `V_new = 5 / 0.25 = 20 повторений`
(то есть вместо 5 подтягиваний делаешь 20 австралийских — эквивалентная нагрузка на мышцы, но в 4 раза меньше на связки).

При замене на более тяжёлое — обратная логика:
- 5 подтягиваний (4) → передний вис tucked (7): `K_diff = 7/4 = 1.75`, `V_new = 5/1.75 ≈ 3 повторения` (округляется вверх).

### 7.3. Относительная сила
```
R = BodyMass / Weight  (для подводящих)
или
PullupStrengthRatio = maxPullups × bodyMass / (height - 100)
```
Используется в рекомендациях и для фильтрации упражнений по доступности.

### 7.4. Возрастной коэффициент
```
K_age = 1.0                              если age < 30
K_age = 1.0 - (age - 30) × 0.005         если 30 ≤ age < 50
K_age = 0.9 - (age - 50) × 0.01          если age ≥ 50
```
Для пользователя 38 лет: `K_age = 1.0 - 8 × 0.005 = 0.96` → плановый объём × 0.96.

### 7.5. Индекс стресса
Простая интегральная формула для MVP (без гаджетов):
```
sleep_score   = clamp(sleep_hours / 8, 0, 1)        // 0..1
mood_score    = mood / 10                            // 0..1
soreness_score = 1 - (soreness / 10)                 // 0..1 (меньше забитости = лучше)

I_stress = 1 - (sleep_score × 0.4 + mood_score × 0.3 + soreness_score × 0.3)
```
- `I_stress < 0.2` → зелёная зона, можно работать в полную силу
- `0.2 ≤ I_stress < 0.4` → жёлтая, снизить интенсивность на 10-15%
- `I_stress ≥ 0.4` → красная, заменить статику на мобильность, ВИИТ на LISS

### 7.6. Рекомендованная длительность круга
```
T_round = Σ (reps × time_per_rep) + transition_sec
time_per_rep = 2 сек (для среднего темпа), 1.5 сек (для быстрого)
transition_sec = 10 (между снарядами), 0 (домашняя площадка)
```
Используется для прогноза количества кругов в AMRAP.

## 11. UX «Быстрой замены» в круге таймера

```
┌──────────────────────────────┐
│   18:42            Круг 7/30 │
│                              │
│   ┌──────────────────────┐   │
│   │   05:00              │   │  ← большой таймер
│   │   осталось           │   │
│   └──────────────────────┘   │
│                              │
│   Упражнения в круге:        │
│   ┌──────────────────────┐   │
│   │ ✅ Подтягивания 5/5  │   │  ← тап по карточке → контекстное меню
│   │    коэф. 4 · тяга    │   │
│   └──────────────────────┘   │
│   ┌──────────────────────┐   │
│   │ ⏳ Брусья 0/10      │   │
│   │    коэф. 3 · жим     │   │
│   └──────────────────────┘   │
│   ┌──────────────────────┐   │
│   │ ⏳ Кор 0/15          │   │
│   │    коэф. 1 · core    │   │
│   └──────────────────────┘   │
│                              │
│  [⏸ Пауза] [⏹ Стоп] [🎤]    │
└──────────────────────────────┘
```

**Поток замены:**
1. Тап по карточке упражнения в круге → контекстное меню: «Заменить», «Пропустить», «Отметить выполненным»
2. Тап «Заменить» → модалка со списком альтернатив того же паттерна (тяга/жим/кор), отсортированных от лёгких к тяжёлым по коэф. нагрузки
3. Тап по альтернативе → превью пересчёта:
   ```
   Замена: Подтягивания → Австралийские
   ────────────────────────────────────
   Коэф. нагрузки:   4 → 1  (↓75%)
   Объём:            5 → 20 повторений
   Целевые мышцы:    Широчайшие, бицепс → те же + нижняя трапеция
   Причина:          ↓ стресс связок под бицепсом
   ────────────────────────────────────
   [Отмена]  [Применить]
   ```
4. После «Применить» — таймер не останавливается, карточка меняется, в историю тренировки пишется substitution

## 13. AI Provider — абстракция

```typescript
// lib/ai/types.ts
interface AIProvider {
  id: string;
  name: string;
  chat(messages: ChatMessage[], options?: ChatOptions): Promise<ChatResponse>;
  isAvailable(): Promise<boolean>;
}

// Реализации:
// 1. ZAiProvider     — через z-ai-web-dev-sdk (бэкенд Next.js)
// 2. WebLLMProvider  — клиентский, через WebLLM + WebGPU
// 3. CustomURLProvider — POST на {customUrl}/v1/chat/completions (Ollama / llama.cpp / LM Studio)
```

В настройках пользователь выбирает провайдера и (для кастомного URL) указывает адрес. Чат доступен с экрана «AI-ассистент» и из контекстных подсказок в тренировке/упражнении.

Системный промпт LLM включает профиль пользователя, текущую тренировку и научную базу приложения — чтобы ответы были релевантны и конкретны.

## 14. TTS и голосовое управление

### TTS (озвучка таймера)
- Web Speech API (`window.speechSynthesis`)
- Кастомные фразы на RU/EN: «Круг N, пошёл», «10 секунд», «Пауза», «Тренировка завершена»
- Включается/выключается в настройках
- Выбор голоса в настройках (из доступных в браузере)

### Голосовое управление
- Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`)
- Команды на RU/EN:
  - «пауза» / «pause» → поставить на паузу
  - «продолжить» / «resume» → снять с паузы
  - «стоп» / «stop» → остановить тренировку
  - «следующий» / «next» → перейти к следующему упражнению
  - «замена» / «substitute» → открыть модалку замены
- Включается/выключается в настройках
- Распознавание непрерывное во время активного таймера

> Обе фичи не требуют внешних зависимостей — работают из коробки в современных браузерах, включая Chrome на Android (важно для Pixel 9).

## 15. Архитектурные принципы для будущего порта

1. **Чистая бизнес-логика** — формулы, расчёты нагрузки, алгоритмы замены, типы упражнений — в отдельных модулях `lib/*.ts` без импортов из React/Next.
2. **Типы данных** — общие TypeScript-типы в `lib/types.ts`, переиспользуемые между фронтендом, бэкендом и (будущим) мобильным приложением.
3. **API-first** — фронтенд никогда не лезет в БД напрямую, только через `/api/*` эндпоинты. Это позволит в нативном приложении переиспользовать те же эндпоинты (или локальный сервер).
4. **i18n-готовность** — все строки через `i18n`-словарь с самого начала.
5. **Минимум зависимостей** — никаких тяжёлых UI-библиотек сверх shadcn/ui, никаких ORM сверх Prisma, никаких state management сверх Zustand + TanStack Query.

## 17. Риски и заметки

- **Web Speech API** на iOS Safari ограничена (TTS работает, SpeechRecognition — почти нет). Для пользователей iPhone голосовое управление может не работать — покажем warning в настройках.
- **WebLLM** требует WebGPU — работает в Chrome/Edge на Android, в Safari пока нет. Для пользователей без WebGPU — fallback на Z.AI или кастомный URL.
- **3D-визуализация** отложена на Фазу 3 — это дорого и долго, в MVP обходимся SVG/GIF.
- **Синк с Apple Health / Google Fit** в чистом вебе почти невозможен (нет нативных API), поэтому отложен до нативного приложения.
- **Размер БД** — каталог упражнений и техник предзаполнен seed-скриптом. Текст на RU/EN хранится в самой БД, а не в коде, для гибкости.
